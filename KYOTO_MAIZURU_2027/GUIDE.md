# 京都・舞鶴 2027 行程網頁：說明與製作指引

這份文件說明 `index.html` 的內容、結構和資料格式，也整理了製作類似旅遊行程網頁時可以照著走的步驟，以及完成後的檢查清單。

---

## 1. 網頁概述

| 項目 | 內容 |
|---|---|
| 用途 | 8 天 7 夜（2027/6/4–6/11）京都・舞鶴自由行的行程手冊，出發前規劃、旅途中查看都能用 |
| 檔案 | `index.html`（單一檔案，含 CSS、範本、資料、程式）＋ `js/vue.global.prod.js`（Vue 3，本機檔） |
| 語言 | 繁體中文／日文，右下角按鈕切換 |
| 外觀 | 淺色／深色模式，跟隨系統或手動切換；手機版有 16px 左右邊距 |
| 不需要 | 不需要伺服器、不需要建置，直接用瀏覽器打開 `index.html` 即可 |
| 記憶 | 語言、深淺色、方案選擇、清單勾選、出示區自訂網址、捲動位置，都存在瀏覽器的 `localStorage`（key：`kyoto2027-state`），只存在那一台裝置 |

## 2. 頁面區塊（由上到下）

1. **封面**：標題、日期、去回程航班卡片。
2. **導覽列**：固定在上方，捲動時自動標示目前區塊；手機版可左右滑動。
3. **總覽**：每天一行的摘要表＋全程路線地圖。
4. **住宿**：每段住宿的晚數、日期、飯店、說明。手機版會改成直排。
5. **Day 1–8**：每天一張卡片，包含：
   - 時間軸：地點（有時間）和移動（較小字、無時間）兩種項目。
   - 方案切換（Day 2、Day 3）：按鈕切換 A／B／C，時間軸、地圖、導航一起換。
   - 當日路線圖（Google Maps 嵌入）。
   - 分段導航按鈕：開 Google Maps 大眾運輸／步行導航；設定裡可改成「從目前位置出發」。
   - 備註（黃色區塊）。
   - 巴士、遊覽船這類可能臨時改行程的項目，下方有時刻表按鈕。
6. **購物**：臨時想逛的店，點卡片從目前位置導航過去。
7. **出示**：入境、領票、上車時要出示的網頁（Visit Japan Web、JR 訂位、WEST QR、黑松號），可以改網址、自己新增連結。
8. **提醒**：ICOCA、周遊券、入境、SIM 卡、退稅新制等。
9. **確認清單**：依時間分組的預訂與確認事項，可勾選；有官網或預約網址的會有按鈕。
10. **右下角按鈕**：語言、深淺色、導航起點、回到頂端。

## 3. 資料結構（改內容時看這裡）

所有內容都在第二個 `<script>` 裡，改資料不用動版面。

### 3.1 小工具函式

| 函式 | 用途 | 範例 |
|---|---|---|
| `L(zh, ja)` | 一段中日對照文字 | `L("抵達京都", "京都到着")` |
| `P(t, zh, ja, links)` | 時間軸的「地點」項目 | `P("13:15", ["標題", "說明"], ["タイトル", "説明"])` |
| `M(zh, ja, links)` | 時間軸的「移動」項目 | `M(["西舞鶴 → 東舞鶴", "JR 約 7 分鐘"], [...])` |
| `G(from, to, mode, zh, ja)` | 分段導航按鈕；`mode` 只用 `"transit"` 或 `"walking"` | `G("京都駅", HOTEL, "transit", "京都站 → Potel", "京都駅 → Potel")` |
| `C(id, 分組, 標籤, 標題, 日期, 副標, 說明, 連結)` | 確認清單項目 | 見 `CHECKS` |
| `K(zh, ja, url)` | 連結按鈕（清單項目、時間軸都用）；按鈕文字隨語言切換，網址固定一個 | `K("遊覽船網路預約", "遊覧船ネット予約", "https://...")` |
| `SH(id)` | 時間軸的「出示：○○」按鈕，點了捲到出示區對應的卡片並亮框；`id` 是 `SHOWS` 的 id，按鈕文字自動用卡片名稱（改過網址也一樣） | `[SH("vjw")]` |
| `S(查詢字, zh, ja, 營業時間)` | 購物卡片 | 見 `SHOPS` |

`P`／`M` 的最後一個參數 `links` 是選填的，放 `K(...)` 陣列，時間軸下方就會出現連結按鈕。常用的連結定義成常數，時間軸和確認清單共用，改網址只要改一處：

| 常數 | 內容 | 來源 |
|---|---|---|
| `BUS_NISHI` | 大江線（西舞鶴站 ↔ とれとれセンター） | 京都交通官方 PDF |
| `BUS_MIHAMA` | 三浜線（東舞鶴站 ↔ 引揚記念館） | 京都交通官方 PDF |
| `BUS_AKA` | 東西循環線右回り（赤れんがパーク・市役所前 → 東舞鶴站） | 京都交通官方 PDF |
| `JR_NISHI` | 西舞鶴站 東舞鶴方面 | JR 西日本（JRおでかけネット） |
| `JR_HIGASHI` | 東舞鶴站 西舞鶴・綾部方面（特急まいづる往京都） | JR 西日本（JRおでかけネット） |
| `BOAT_TIME` | 舞鶴灣遊覽船 運航・票價 | 遊覽船官網 |
| `KAMABOKO` | 舞鶴かまぼこ手形 使用說明 | 京都交通官網 |

### 3.2 主要資料

| 常數 | 內容 |
|---|---|
| `UI` | 介面文字（`zh`、`ja` 兩組，key 要一模一樣） |
| `FLIGHTS` | 封面航班卡片 |
| `STAYS` / `STAY_NAMES` | 住宿表／每天卡片上的住宿名稱 |
| `DAYS` | 每天的行程（見下） |
| `TAGS` / `GROUPS` / `CHECKS` | 清單的標籤、分組、項目 |
| `SHOWS` | 出示區預設卡片 |
| `TIPS` | 提醒 |
| `SHOPS` | 購物卡片 |
| `ICONS` | 圖示（SVG path） |

### 3.3 一天的格式

```js
{
  id: "d2", n: "Day 2", md: "6/5", wd: 6,   // wd：0=日 … 6=六
  stay: "bellmare",                          // 對應 STAY_NAMES
  title: L(...), short: L(...),              // short 用在總覽表
  badge: { cls: "b-ok", ...L(...) },         // 選填
  timeline: [P(...), M(...)],                // 沒有方案時
  legs: [G(...)], map: ["地點1", "地點2"],
  notes: [L("<b>粗體</b>說明", "...")],      // notes、intro、TIPS 可以用 <b>；時間軸文字不行
}
```

有方案時，把 `timeline`／`legs`／`map` 移到 `plans` 裡：

```js
plans: {
  A: { label: L(...), intro: L(...), next: { d3: "A" }, timeline, legs, map },
  B: { label: L(...), intro: L(...), next: { d3: "B" }, timeline, legs, map },
}
```

- `next`：選這個方案時，自動把別天切到哪個方案（Day 2 → Day 3）。
- `fits`：選這個方案時，別天必須是哪些方案，不是就切成第一個（Day 3 → Day 2），例如 `fits: { d2: ["A", "B"] }`。
- 方案的顯示順序就是 `plans` 裡 key 的順序，第一個是預設方案；字母和標題開頭要一致（`A: { label: L("A ...") }`）。改字母時，`next`、`fits`、別天說明裡的「6/5 選 A 或 B」、注意事項的（A、B）標註、確認清單標題都要一起改。
- 共用的開頭／結尾用陣列展開，例如 `[...D2_HEAD, ...]`。

目前的方案對應：

| Day 2（6/5） | Day 3（6/6） |
|---|---|
| A 海鮮市場＋吉原入江 | A 紅磚公園＋遊覽船 |

| C 田邊城跡＋紅磚公園黃昏 | B 引揚記念館＋紅磚公園 |

## 4. 製作類似網頁的步驟

### 4.1 先準備的資訊

- 日期、人數、航班（班號、時刻、航廈）。
- 每晚住哪裡、地址、離車站多遠。
- 一定要去的地方、固定行程（看醫生、指定店家等）。
- 要不要買周遊券、哪幾天用。
- 偏好與限制（見 4.3）。

### 4.2 請 AI 製作時可以這樣說

> 參考 `GUIDE.md` 和 `index.html` 的結構，幫我做一個新的行程網頁 `index.html`：
> 日期 ○○、航班 ○○、住宿 ○○、必去 ○○。
> 遵守 GUIDE.md 第 4.3 節的偏好，完成後照第 5 節逐項檢查並回報。

建議一步一步來：先排行程和時間，確認後再加連結、出示區、清單，最後做翻譯和總檢查。

### 4.3 這次確定的偏好（下次直接沿用）

**行程**
- 全程只用電車、巴士、步行，不排計程車。
- 宗教場所只排外觀或沿途經過，不排入內參觀，除非另外指定。
- 不在頁面上寫「已訂」「確定可以訂」這類訂位狀態；機票、飯店仍列在確認清單裡給自己核對。
- 有兩三種玩法的日子，用方案 A／B／C 切換，相鄰兩天的方案要能互相連動。

**連結**
- 機票、飯店不放預訂連結。
- 確認清單：有預約或查資料需要的項目放官網／預約按鈕。
- 時間軸：只在巴士、遊覽船、班次少的 JR（舞鶴線、特急まいづる）這類「玩過頭要臨時改班次」的項目放時刻表連結；不放跳到確認清單的按鈕（確認事項在清單裡統一處理）。
- 時刻表一律用官方來源：JR 用 JR 西日本「JRおでかけネット」的駅時刻表，巴士用京都交通官網的路線時刻表 PDF。不用 Yahoo!、NAVITIME、Jorudan 這類轉載網站（Jorudan 手機版會被導到登入頁）。
- JRおでかけネット只能選約 6 週內的日期，連結不帶日期參數，打開後自己切換日期。
- 臨時要買、在現場才用得到的票券（例：舞鶴かまぼこ手形），連結放在買票那一步；詳細的「哪些方案用得到」寫在當天備註，時間軸只留一句。
- 出示區：放入境、領票、上車要出示的網頁，讓自己可以改成個人訂位頁。
- 時間軸上要出示東西的那一步，放 `SH(...)` 按鈕跳到出示區的卡片（目前：6/4 入境 → Visit Japan Web、6/4 領周遊券 → JR 訂位紀錄、6/5 黑松號上車 → 黑松號訂位確認、6/11 HARUKA → WEST QR、6/11 退稅海關確認 → Visit Japan Web）。
- 官網有繁體中文版就用中文版網址（不需要依語言切換網址）；沒有中文版的才用原本的網址。
- 網址要實際打開測試過（例如 Visit Japan Web 要用 `www.vjw.digital.go.jp`，少了 `www.` 會打不開）。

**版面**
- 確認清單放在網頁最後。
- 出示區放在提醒之前。
- 程式裡不留註解。

**資料**
- 營業時間、票價、時刻要上網查，查不到或資料舊的要寫「出發前確認」，並附上查證年份（例如「2024 年版時刻」）。
- 交通時間是自己估的，要寫「約」，並提醒用 Google Maps 確認。
- 巴士要看「土日祝運休」標記（京都交通 PDF 的 ※），用旅行當天的星期對班次。
- 舞鶴市內走得到的路段（約 20–25 分鐘）以步行為主，巴士寫成「巴士備案」：寫出當天可搭的班次、上車站名、付款方式（京都交通不能刷 IC 卡，付現金或用かまぼこ手形），時刻表連結保留。走不到的（三浜線往引揚記念館）才排巴士為主。
- 時刻表有改正日的要寫出版本（例：「2026/4/4 改正版」），JR 和巴士每年春天可能改點。

## 5. 檢查清單

### 5.1 行程與時間

- [ ] 每天的時間能銜接：移動時間＋停留時間不會重疊。
- [ ] 每個日期的星期正確，和景點公休日對過（例：鐵道博物館週三休、引揚記念館週三休）。
- [ ] 有「最後入場／停止受理」的地方（例：三室戸寺 15:10、月桂冠 16:00）排在截止前。
- [ ] 一小時一班或一天幾班的車（JR 舞鶴線、三浜線），有寫錯過的後果和替代方案。
- [ ] 建議搭的特急（包括西舞鶴 → 東舞鶴的まいづる）是全車指定席的，都有寫「先劃位」。
- [ ] 入住時間 = 下車時間＋步行時間，不要寫得比實際早；飯店離車站遠的，晚餐排在車站附近、入住之前，避免來回走。
- [ ] 巴士備案的班次不要跟前一個行程的時間重疊（例：遊覽船 13:00–13:30，就不能寫 13:25 的巴士）。
- [ ] 用「旅行者走一遍」的方式，從第一天到最後一天逐段算時間。
- [ ] 預約開放日算對（JR 指定席 1 個月前 10:00、黑松號 3 個月前 10:00、遊覽船 90 天前）。
- [ ] 抵達日：入境、領票的排隊時間有預留。
- [ ] 回程日：退稅新制要在託運前做海關確認，抵達機場時間要夠（這次搭 11:00 HARUKA，約 12:20 到，起飛前約 2 小時 50 分；最晚 11:30）。早上排購物時，寫出要逛的店幾點開門、幾點要準備離開去搭車（不寫「不排某地」這類理由）。

### 5.2 交通

- [ ] 沒有計程車（畫面、導航按鈕都沒有）。
- [ ] 每段導航都是 `transit` 或 `walking`。
- [ ] 周遊券的使用期間涵蓋長途 JR；不含的路線（地鐵、私鐵、巴士、期間外的車）有寫清楚。
- [ ] 全車指定席的特急有提醒先劃位。

### 5.3 網頁功能（用瀏覽器實際點）

- [ ] 方案切換：時間軸、地圖、導航一起換；相鄰兩天的連動和「（建議）」標示正確。
- [ ] 時間軸的時刻表按鈕只出現在巴士、遊覽船、舞鶴的 JR，打得開，而且是官方來源。
- [ ] 所有外部連結打得開，開在新分頁。
- [ ] 有繁中官網的連結都指到繁中頁。
- [ ] 清單勾選、方案選擇、語言、深淺色、出示區自訂網址，重新整理後還在。
- [ ] 出示區「改網址」「新增連結」「刪除」可用。
- [ ] 時間軸的「出示：○○」按鈕點了會捲到出示區對應卡片並短暫亮框，在原分頁跳轉、不開新分頁。
- [ ] 手機寬度：左右不會滑動，導覽列可橫滑，表格改直排。
- [ ] 深色模式文字看得清楚。
- [ ] 導覽列順序和頁面區塊順序一致。

### 5.4 翻譯

- [ ] 每一段 `L(zh, ja)` 兩邊都有內容。
- [ ] `UI.zh` 和 `UI.ja` 的 key 一樣多、一樣名稱。
- [ ] 切到日文時，標題、按鈕、日期星期都是日文。
- [ ] 店名、站名在中文版保留日文原名或常用中文名，不要混用。
- [ ] 同一個名詞全篇寫法一致：記念館（不寫「紀念館」）、巴士（不寫「公車」）、大人票價（不寫「成人票」）、舞鶴灣遊覽船。
- [ ] 日文句子不要講到一半：「〜へ」「〜を」這類指南常見的省略可以用，但動詞不能省到看不懂（例：「日付印を」要寫成「日付印を押してもらう」，「普通に」要寫成「普通に乗る」）。

### 5.5 程式

- [ ] 沒有註解（`<!-- -->`、`/* */`、`//`）。
- [ ] 語法沒有錯誤（瀏覽器開發者工具 Console 沒有紅字）。
- [ ] 範本裡用到的 `u.xxx` 在 `UI` 裡都有。
- [ ] 範本和資料裡用到的圖示在 `ICONS` 裡都有。
- [ ] 清單 id 沒有重複；時間軸 `links` 的每個連結都有中日文字和網址。

## 6. 注意事項

- **編輯器覆蓋問題**：VS Code 如果出現「檔案已在磁碟上變更」，要選重新載入，不要選覆蓋，否則會把新版本蓋掉。這次就發生過一次，時間軸的巴士連結整段消失。
- **自動格式化**：存檔時的自動格式化（例如 Prettier）會把程式拆成很多行，不影響功能，但檔案會變長。
- **瀏覽器資料**：勾選和自訂網址只存在該裝置的瀏覽器，換手機或清除瀏覽資料就會不見。
- **Vue 檔案**：`js/vue.global.prod.js` 要跟 `index.html` 放在一起，搬移資料夾時兩個一起搬。
